Found in PR #33 review A (A4), pinned there by a_forks_own_step_that_repeats_a_parent_total_is_still_dropped_as_a_copy. Under PR #32's turn-inference rule (and PR #33's Unmarked boundary for migrated user forks), a counter whose total equals one the parent root reported voids an inferred start, and the copied_total rule then assigns that same counter to the parent as a copy. A fork (or a migrated subagent with a boundary past its end) whose first own response repeats the parent's next response in all six counts, as a retried prompt can, loses that usage with coverage complete and no diagnostic: synthetic P4b/P4c report 160 against a real 220 (main: 320). Varying reasoning-token counts keep it rare. Fix direction (review A4 option 1): treat the counter that voids a start as undecided rather than as a copy, so it becomes a codex-history-boundary-unverified gap; C3's totals stay at 200 and its undecided count rises by one. Design §3.4, the research note and the release record already describe the drop.
